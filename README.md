# Echo — `echo-maze`

A 2D top-down stealth/horror game where the screen is completely black and you see the world through **the echo of your own sound**: you make a noise, a cone-shaped wave travels forward, hits walls and creatures, and comes back as a train of returning arcs; you have to read the shape of each arc. Every sound you make is also heard by the things in the dark — they cannot be killed, only escaped, and one touch kills. This is a project for the Game Theory course at Iran University of Science and Technology.

Ten chapters: an enemy-free maze that teaches the language, then the descent — the corridor, the flooded wing, the listening room, the sump stairs, the boiler run, the dry well, the cold store, the floodgate, and the sump at the bottom. English only, **Windows and Linux PC** with a microphone and headphones.

## Editor version

**Unity 6000.6.3f1** — exactly this version. Opening the project with a newer editor upgrades the files one way. Required modules and details in [Docs/TEAM_SETUP.md](Docs/TEAM_SETUP.md).

## Opening and running

```
Unity Hub ▸ Add project from disk ▸ this folder
Tools ▸ Echo Maze ▸ Build Everything        (generates settings, scenes, build list)
Assets/Scenes/Boot.unity ▸ Play             (PLAY ▸ Level01_Maze)
```

`Boot` is the menu the game starts on, and it carries the story's **chapters** page: the ten rooms as one rail
of nodes, each node reading out its difficulty, what shares the room, the sentence that leads into it, and the
best run it has been walked in. The room you have earned is open, the ones behind you carry their record, and
the ones ahead stay sealed until the room before them is finished. Choosing a node walks a pulse of light down
the thread to it. Progress is saved per scene in `PlayerPrefs`, so the first button becomes **continue** once
there is something to continue. Every chapter of the run is playable and ends on the victory panel. `Sandbox`
is the mechanical playground for the echo ray fan — it still works, it is just no longer what "run the game"
means.

Every scene in `Assets/Scenes` is generated by the editor code in `Assets/Scripts/Editor`, so a fresh clone is
only a game after **Build Everything** has run once. It is idempotent: re-running it repairs and re-wires, it
does not stack a second copy of anything. The other items on that menu are `Build Boot Scene`, `Build Chapter
Scenes` (one scene per chapter in the catalogue), `Apply Build Scenes` and `Build Player`.

To produce and launch the Linux player from a terminal:

```
"/home/<you>/Unity/Hub/Editor/6000.6.3f1-x86_64/Editor/Unity" -batchmode -quit -projectPath . \
    -executeMethod EchoMaze.EditorTools.PlayerBuild.Build
./Builds/echo-maze
```

The executable is `Builds/echo-maze` (the leaf of the build path; on Linux it gets no extension). `Builds/` is
git-ignored. The build is a Development build, so it writes a log —
`~/.config/unity3d/DefaultCompany/echo-maze/Player.log` on this project's current settings
(`companyName` / `productName`).

Controls that exist in this build, as the menu prints them:

```
WASD move · mouse aim · Space shout (hold to charge) · F pulse
Shift move silently · E open a door / take the exit · Esc pause
```

The **how to play** page on that menu is the same information as a guide rather than a document outside the
game: seven cards — reading the dark, the waves you can make, moving and what it costs, what lives in the
dark, the rest of the room, your voice, and the descent (how the chapters page works, and what the seal on a
node means). The wording lives in `Assets/Scripts/Runtime/UI/GuidePages.cs`, and `GuidePageTests` fails the
suite if a reworded card no longer fits the generated page.

Listen mode (`Ctrl`) and the decoy marble are **M2** work and are deliberately not on the menu yet. The first
room has no enemy in it; the Crawler walks every chapter after it. Spike and absorber exist as scenes and
tuning but no chapter places them yet. The build is produced with the platform set to **Linux64**.

## Sound input and platform limits

All sound input sits behind one abstraction layer called `IEchoSource`. **`Sandbox` now runs with `sourceMode = Microphone`**: the scene opens the capture device and pings on your voice. Measured on Linux (`6000.6.3f1`, PipeWire) on 2026-10-28: `Microphone.devices` returns the real inputs, `Microphone.Start` records, and the room's noise floor sits at ~0.003 RMS against a `gateOpenRms` of 0.02. Two things the first run taught us: the ring buffer is uninitialised for its first window (so the source discards 0.25 s of capture before it trusts the level), and `GetPosition` advances in blocks, so a frame with no new audio must not be read as silence.

If a machine has no usable input, the director logs one warning and falls back to `Simulated` (a constant `simulatedLoudness` on a timer), and `ManualOnly` + Space remain available everywhere — nobody is blocked by a missing microphone. `EchoTuningProfile.microphoneDevice` is only the *seed* for the choice: with it empty the game takes the first device whose name is not a `Monitor of …`, because a monitor is your own speaker output and the game would answer its own sound effects. The choice itself is in-game: the calibration page on `Boot` has an **input** button that steps `auto ▸ device ▸ device …`, re-scans when a device appears or disappears, applies on the press without restarting, and writes the name to `PlayerPrefs` (`echo.mic.device`) as a preference — a saved name that has left the machine falls back to `auto` rather than failing to open. Nothing has to be pasted into a ScriptableObject in a terminal any more (see the 2026-10-29 entry in [Docs/DESIGN_DECISIONS.md](Docs/DESIGN_DECISIONS.md)). The rule lives in `MicDeviceChoice` and is covered by EditMode tests; what still needs a person is whether the gate opens on a real voice in the **player build** ([Docs/MIC_TEST_MATRIX.md](Docs/MIC_TEST_MATRIX.md) row 2). Details in [Docs/DESIGN_DECISIONS.md](Docs/DESIGN_DECISIONS.md).

## Folder layout

```
Assets/Scenes            Sandbox (mechanic test) · Boot (menu) · one scene per chapter (Level01_Maze … Level10_Sump)
Assets/Scripts/Runtime   Core (echo) · Audio (sound input) · Gameplay · Data · UI · Debug
Assets/Scripts/Editor    Editor tooling (echo debug window, level validation, Validate Git Setup)
Assets/Tests             EditMode (arc math / readability / hearing) and PlayMode (scene validation)
Assets/Data              Balancing ScriptableObjects: echo parameters, enemies, levels
Assets/Art               Arc shader, materials, fonts
Docs                     PLAN, SCOPE_CUTS, GIT, TEAM_SETUP, TUNING, DESIGN_DECISIONS, QA and test docs (the live GDD is at the repo root)
Tools                    unity-yaml-merge.sh — the git merge driver wrapper (see Docs/TEAM_SETUP.md)
```
